# Авторизация и роли

1. Установите зависимости: `npm install`. После этого соберите стили командой `npm run build:css`.
2. Создайте `.env` на основе `.env.example` и вставьте ключ проекта в `SUPABASE_SECRET_KEY` (предпочтительно серверный secret/service_role key; для чтения профиля также поддерживается publishable/anon key благодаря передаче JWT пользователя). Не публикуйте secret/service_role key и не добавляйте `.env` в Git.
3. В Supabase откройте Authentication → URL Configuration. В Site URL укажите адрес приложения. В Redirect URLs добавьте `http://localhost:3000/**` для локальной разработки и адрес опубликованного сайта.
4. В Authentication → Providers → Email должна быть включена Email provider и подтверждение почты (Confirm email).
5. Встроенная отправка Supabase подходит только для ограниченного тестирования: адрес получателя должен быть разрешён Supabase (член команды проекта). Это ограничение оставлено намеренно.
6. Запуск: `npm start`, затем `http://localhost:3000/login`.

При регистрации триггер `handle_new_auth_user` создаёт запись профиля в `public.users` и назначает роль «Агент» по умолчанию. Руководитель должен изменить `id_role` в `public.users` для сотрудников с другой ролью. Роли берутся из таблицы `public.roles`, не из пользовательских метаданных.

Распределение доступа:
- Руководитель, Менеджер: все разделы.
- Мастер производства: Главная, Комплектующие, Производство.
- Кладовщик: Главная, Комплектующие, Склад.
- Агент: Главная, Комплектующие, Заявки.

API проверяет access token и роль на сервере. Publishable key в `Public/js/auth.js` является публичным ключом Supabase; серверный secret/service-role key остаётся только в `.env`.
